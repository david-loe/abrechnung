# Test audit — 2026-10-28

Baseline: `973d3e1f` (`origin/main` when this branch was created). All original package checks passed: **310 backend, 118 common and 113 frontend tests**. This inventory covers every original suite, plus the browser, production and dependency checks. Retained examples were inspected for their boundary, assertion, independence and failure behavior; rewriting every already-valid example would add churn without improving its specification.

The target is preserved business assurance, not a test-count or line-coverage quota. Existing long workflows now register one complete story with named assertion-isolated steps. Their lower count of top-level AVA tests does not mean their previous business checks were deleted. New state examples are individually selectable and create their own prerequisites.

## Product defects exposed

1. All four booking controllers wrapped a rejected typed error in `Error`, converting forbidden or missing bookings into HTTP 500 when every item failed. Preserve the original error/status; mixed batches retain their successful/rejected item results.
2. A generated professional-share example failed after 23 runs and shrank to **one cent of mixed expenses at 0% professional share** (`seed=-544296449`, counterexample `[[1],0,false]`). A truthiness check treated zero like a missing share and refunded the whole amount. Apply numeric zero to both stage and expense costs; retain explicit zero-share examples alongside generated cases.

## Tradeoffs and boundaries

- Shared-fixture restoration assumes serial backend execution without concurrent manual changes to those same fixtures. Exact-ID cleanup protects unrelated new entities; it does not make shared settings safe for concurrent editing.
- HTTP, Redis and browser examples localize a failure less narrowly and run longer than implementation-level mocks. Individual transition filtering and named story steps provide diagnostics without prescribing internal calls.
- The state model and example tables must change when business rules change. They deliberately do not derive expected transitions from production controller predicates.
- Fast-check and PDF.js are development dependencies. They increase development/build dependency size; they are not imported into the user-facing application bundle. PDF geometry checks avoid full binary/pixel snapshots, so they do not assert every aesthetic detail.
- Property checks sample bounded domains; they are no proof of all numeric inputs. Concrete examples cover known rounding and zero-share regressions.
- Internal scan sizes, exact drawing-call order and exact log strings are deliberately no longer contracts. Observable output, pagination correctness and dedicated MongoDB query-performance checks remain.
- Browser application examples simulate HTTP backend responses and therefore do not claim to be full browser-to-real-backend end-to-end tests. Backend HTTP tests separately exercise the real services.
- No new billing policy is inferred from undocumented behavior. Negative project totals continue to be flagged with zero reimbursement; negative bookkeeping corrections remain covered independently.

Sources and compiled outputs were restored, then all package checks passed again. This is targeted evidence, not a whole-repository mutation score.
